## Usage

```shell
npm i @emoji-platform-data/windows
```

```ts
import { byEmoji, byTitle } from "@emoji-platform-data/windows";

console.log(byEmoji["😂"]);
/*
{
	emoji: "😂",
	keywords: ["crying", "face", "feels", "funny", "haha", "happy", "hehe", "hilarious", "joy", "laugh", "lmao", "lol", "rofl", ...],
	name: "face with tears of joy",
}
*/
```

Emojis can be looked up by their glyph with `byEmoji` or by the PascalCase form of their Emojipedia title with `byTitle`.
`byEmoji` knows each emoji by every glyph platforms write it as, with or without the U+FE0F variation selector, so `byEmoji["⚓️"]` as macOS writes it and `byEmoji["⚓"]` as Twemoji does are the same entry.
Each entry is a `WindowsItem` describing one emoji as the Windows emoji panel -the one <kbd>Win</kbd> + <kbd>.</kbd> opens- knows it.

`name` is how Windows names the emoji, which is its Unicode CLDR name, such as `octopus` for 🐙.
`keywords` are the other terms the panel matches searches against: 1,637 of the 1,643 emoji have them, averaging 7.17 each.
They run from CLDR's annotations to slang and emoticons, such as `ttyl` and `g2g` for 👋, and `:-o` and `no way` for 😲.
Over 1,100 of them are in no other source in `emoji-platform-data`.

This package contains only static JSON and type declarations: it has no runtime dependencies.
It is one of several data packages generated by the [`JoshuaKGoldberg/emoji-platform-data` repository](https://github.com/JoshuaKGoldberg/emoji-platform-data), which publishes a combined [`emoji-platform-data`](http://npmjs.com/package/emoji-platform-data) package with data from all supported platforms.

## Where This Data Comes From

Windows doesn't publish its emoji keywords, and they aren't the [Fluent UI emoji](https://github.com/microsoft/fluentui-emoji) metadata in [`@emoji-platform-data/fluemoji`](https://npmjs.com/package/@emoji-platform-data/fluemoji), which has far fewer.
The emoji panel reads them from `datamap.0409.dat`, a file that each Windows display language installs as part of its basic typing features.
That file was read out of the newest retail Windows 11 release's en-US typing features, downloaded from Windows Update, and committed as a snapshot so that building this repository doesn't depend on a network fetch.
See [`DEVELOPMENT.md`](https://github.com/JoshuaKGoldberg/emoji-platform-data/blob/main/packages/windows/DEVELOPMENT.md) for how that extraction works and how to refresh it.

The data also lists each skin tone combination of the emoji that show more than one person, such as 🫱🏻‍🫲🏼.
Those are left out here: their keywords are their base emoji's, plus the names of their skin tones.

The panel's categories and order aren't here, since they're part of the panel itself rather than this data.

The names and keywords are Microsoft's.
This package's MIT license covers the code that extracts and packages them, not the underlying data.
No Windows emoji artwork is included: these are text names and keywords only.
