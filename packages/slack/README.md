## Usage

```shell
npm i @emoji-platform-data/slack
```

```ts
import { byEmoji, byTitle } from "@emoji-platform-data/slack";

console.log(byEmoji["🐙"]);
/*
{
	aliases: [],
	category: "Animals & Nature",
	emoji: "🐙",
	keywords: ["animal", "creature", "ocean", "fish"],
	keywordsByLocale: {
		"de-DE": ["Tier", "kreatur", "ozean", "Fisch"],
		"ja-JP": ["動物", "生き物", "海", "魚"],
		...
	},
	name: "octopus",
	namesByLocale: {
		"de-DE": "oktopus",
		"ja-JP": "タコ",
		...
	},
	order: 613,
}
*/
```

Emojis can be looked up by their glyph with `byEmoji` or by the PascalCase form of their Emojipedia title with `byTitle`.
Each entry is a `SlackItem` describing one emoji as Slack's own emoji picker knows it.

`name` is the shortcode Slack writes the emoji as, and `aliases` are the others it accepts: typing any of them between colons sends the emoji.
`keywords` are the extra terms the picker matches searches against in English, which is how typing `celebrate` finds 🎉 (`tada`).
1,845 of the 1,911 emoji have them, averaging 5.69 each; the 66 without are mostly newer people variants, such as the ones facing right, and less common flags.
`order` is where the emoji falls in the picker's overall order, counting from the first emoji of its first category.
52 emoji have no `category` or `order`: they're mostly the gender-neutral forms of older people emoji, such as 👮 `cop`, which the picker shows only as their man and woman variants.

### Other Locales

Slack translates its emoji picker into 11 locales besides English: `de-DE`, `en-GB`, `es-ES`, `es-LA`, `fr-FR`, `it-IT`, `ja-JP`, `ko-KR`, `pt-BR`, `zh-CN`, and `zh-TW`.

`keywordsByLocale` holds the terms the picker searches in each of those, and `namesByLocale` the name it shows the emoji by.
Slack translates each English keyword once, rather than once per emoji, so an entry's keywords in a locale line up with its English ones.
A term the locale has no translation for stays in English, as it does in the picker, which is why `en-GB` is nearly all English: it only swaps out the handful of terms, such as `xoxo` for `xx`, that British English says differently.

Because each word is translated once for every emoji that uses it, a translation can suit one of those emoji better than another.

This package contains only static JSON and type declarations: it has no runtime dependencies.
It is one of several data packages generated by the [`JoshuaKGoldberg/emoji-platform-data` repository](https://github.com/JoshuaKGoldberg/emoji-platform-data), which publishes a combined [`emoji-platform-data`](http://npmjs.com/package/emoji-platform-data) package with data from all supported platforms.

## Where This Data Comes From

Slack doesn't publish its emoji list: it ships inside the web client's JavaScript bundle, which its desktop app loads too.
The shortcodes, categories, and English keywords sit in one module there; the translations are in the client's per-locale string files, keyed by a hash of each English term.
It was all read out of that bundle and committed as a snapshot, so that building this repository doesn't depend on a network fetch of files that change name on every deploy.
See [`.github/DEVELOPMENT.md`](https://github.com/JoshuaKGoldberg/emoji-platform-data/blob/main/.github/DEVELOPMENT.md) for how that extraction works and how to refresh it.

Slack's data also lists every skin tone variant of the emoji that have them.
Those are left out here: their shortcodes are mechanical suffixes on the base emoji's, such as `wave::skin-tone-3`, so they carry no terms of their own.

The shortcodes, keywords, translations, categories, and ordering are Slack's.
This package's MIT license covers the code that extracts and packages them, not the underlying data.
No Slack emoji artwork is included: these are text names only.
