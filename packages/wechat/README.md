## Usage

```shell
npm i @emoji-platform-data/wechat
```

```ts
import { byEmoji, byTitle } from "@emoji-platform-data/wechat";

console.log(byEmoji["🐙"]);
/*
{
	category: "动物",
	emoji: "🐙",
	keywords: ["章鱼", "ocean", "octopus", "tentacle", "章魚", "八爪魚"],
	order: 203,
}
*/
```

Emojis can be looked up by their glyph with `byEmoji` or by the PascalCase form of their Emojipedia title with `byTitle`.
Each entry is a `WeChatItem` describing one emoji as WeChat's own emoji picker knows it.

`keywords` are the terms the picker matches searches against, and they're the reason this package exists: WeChat writes them in Simplified Chinese, Traditional Chinese and English all at once, so 🎉 answers to `庆祝`, `慶祝`, `party` and `confetti` alike.
1,759 of the 1,816 emoji have them, averaging 6.08 each, for 10,689 terms in total.

`category` is the picker's own grouping, named as WeChat names it: `表情与手势`, `动物`, `自然`, `食物与饮料`, `活动`, `旅行与地点`, `物体`, `符号`, and `人物`.
`order` is where the emoji falls in the picker's overall order, counting from the first emoji of its first category.
531 emoji have neither: WeChat's search finds them, but its picker doesn't list them.

This package contains only static JSON and type declarations: it has no runtime dependencies.
It is one of several data packages generated by the [`JoshuaKGoldberg/emoji-platform-data` repository](https://github.com/JoshuaKGoldberg/emoji-platform-data), which publishes a combined [`emoji-platform-data`](http://npmjs.com/package/emoji-platform-data) package with data from all supported platforms.

## Where This Data Comes From

WeChat doesn't publish its emoji list, and its desktop clients don't carry one: they know which emoji to draw, but not what to call them.
Its Android app does, in two files -the picker's category listing and its search index- which were read out of the app and committed as a snapshot, so that building this repository doesn't depend on a network fetch.
See [`.github/DEVELOPMENT.md`](https://github.com/JoshuaKGoldberg/emoji-platform-data/blob/main/.github/DEVELOPMENT.md) for how that extraction works and how to refresh it.

WeChat's picker also gives each emoji a description, such as `笑出眼泪的脸` for 😂.
Those are left out here: they read as translations of the emoji's Unicode name rather than terms anyone would search for, and CLDR already publishes Chinese names for every emoji.
The keywords are the opposite, and are what this package is for -84% of them appear in no CLDR Chinese annotation.

WeChat's own stickers, the `[捂脸]` artwork its picker shows alongside these, aren't here either: they're images rather than unicode emoji, so there's no glyph to key them by.

The keywords, categories, and ordering are WeChat's.
This package's MIT license covers the code that extracts and packages them, not the underlying data.
No WeChat emoji artwork is included: these are text names only.
