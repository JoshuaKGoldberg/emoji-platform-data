## Usage

```shell
npm i @emoji-platform-data/gnome
```

```ts
import { byEmoji, byTitle } from "@emoji-platform-data/gnome";

console.log(byEmoji["🐙"]);
/*
{
	category: "Animals & Nature",
	emoji: "🐙",
	keywords: ["animal", "creature", "ocean"],
	keywordsByLocale: {
		de: ["krake", "meer", "oktopus", "tier", "tintenfisch"],
		ja: ["オクトパス", "動物", "軟体動物"],
		...
	},
	name: "octopus",
	namesByLocale: { de: "Oktopus", ja: "タコ", ... },
	order: 660,
}
*/
```

Emojis can be looked up by their glyph with `byEmoji` or by the PascalCase form of their Emojipedia title with `byTitle`.
`byEmoji` knows each emoji by every glyph platforms write it as, with or without the U+FE0F variation selector, so `byEmoji["⚓️"]` as macOS writes it and `byEmoji["⚓"]` as Twemoji does are the same entry.
Each entry is a `GnomeItem` describing one emoji as GNOME's emoji picker -GTK's emoji chooser, the one <kbd>Ctrl</kbd> + <kbd>.</kbd> opens in any GTK text field- knows it.

`name` and `keywords` are what the picker shows and searches in English: every emoji has keywords.
They're the [Unicode CLDR](https://cldr.unicode.org) annotations, by way of [Emojibase](https://emojibase.dev), so most of them are already known to other sources in `emoji-platform-data`.
What GNOME adds is the same for GTK's other locales: `namesByLocale` and `keywordsByLocale`, keyed by locale, such as `de` or `ja`, which the picker searches alongside the English.

`category` is the picker's own section, named as its headings name it: `Smileys & People`, `Body & Clothing`, `Animals & Nature`, `Food & Drink`, `Travel & Places`, `Activities`, `Objects`, `Symbols`, and `Flags`.
`order` is where the emoji falls in the English picker, counting from the first emoji of its first section.
The hair components, such as 🦰, have neither, since the picker doesn't show them.
The 8 emoji new in Emoji 17.0, such as 🫪, have no `order`: GTK's English data is a CLDR release behind its other locales', so only pickers in those locales show them yet.

This package contains only static JSON and type declarations: it has no runtime dependencies.
It is one of several data packages generated by the [`JoshuaKGoldberg/emoji-platform-data` repository](https://github.com/JoshuaKGoldberg/emoji-platform-data), which publishes a combined [`emoji-platform-data`](http://npmjs.com/package/emoji-platform-data) package with data from all supported platforms.

## Where This Data Comes From

GTK commits its emoji data to its own repository, as one [GVariant](https://docs.gtk.org/glib/gvariant-format-strings.html) file per locale under [`gtk/emoji`](https://gitlab.gnome.org/GNOME/gtk/-/tree/main/gtk/emoji).
Those files were read from the newest stable GTK 4 release and committed as a snapshot, so that building this repository doesn't depend on a network fetch.
See [`DEVELOPMENT.md`](https://github.com/JoshuaKGoldberg/emoji-platform-data/blob/main/packages/gnome/DEVELOPMENT.md) for how that extraction works and how to refresh it.

GTK lists each emoji once, with a marker for whether it has skin tone variants, so those variants aren't here.
Some emoji are as GTK writes them rather than fully qualified, such as 🕵‍♂️, since that's what its picker inserts.

The names and keywords are the Unicode CLDR's, under the [Unicode License](https://www.unicode.org/license.txt), as converted by Emojibase and GTK.
No emoji artwork is included: these are text names and keywords only.
